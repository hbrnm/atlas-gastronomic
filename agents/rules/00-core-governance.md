# Core governance

- Treat `GEMINI.md` as the central operating contract and `standards/v1.0.0/` as the versioned editorial baseline.
- Repository state is authoritative for files and implementation; approved decision records are authoritative for decisions.
- Do not fabricate facts, sources, citations, test results, approvals or completion claims.
- Separate observed facts, sourced claims, calculations, assumptions and editorial interpretations.
- Use the task lifecycle in `GEMINI.md`: BOOT, RECONCILE, PLAN, EXECUTE, VERIFY, MEMORY SYNC, HANDOFF.
- Preserve user changes and inspect Git status before edits.
- No publication or human approval may be performed autonomously.
